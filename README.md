## 一、先算清三笔账，别看核心数下单

### CPU：MC的整条主线程只跑在一个核上

实体移动、方块更新、区块加载、红石、刷怪，这些最吃性能的逻辑都串行在主线程里。雨云论坛那篇《开 MC 服该买多大配置》里说得很直接：一台5.8GHz的4核，跑MC会比2.2GHz的16核流畅得多。所以挑机型时先看主频和单核跑分，老款至强E5那种"十几核但2.x GHz"的机器，开百人服反而是灾难。

这也是1.18+版本分水岭的来源——官方页面明确写了，1.18+的资源消耗大约是1.16+的两倍、1.12.2的三倍。同样是100人，跑1.12.2和跑1.21对CPU的要求完全不是一个量级。

### 内存：物理内存 = 服务端堆 + 1.5G余量

托管商公开的分级表口径基本一致：100人在线，纯净/Paper服务端建议10–12GB堆内存，模组服16–32GB。但堆内存不等于物理内存。论坛那条经验公式值得抄下来：**物理内存 = 服务端分配 + 1.5G安全余量**。4G的机器把`-Xmx`写成4G，结果是系统内存不足直接杀进程，表现就是"服务器莫名其妙自己关了"。

另一个反直觉的点：内存不是越大越好。堆开到24GB以上，一次GC暂停可能到200–500ms，玩家能明显感觉到卡顿。这也是下面要讲的群组架构更划算的原因。

### 带宽：100人约10Mbps，但要留余量

MC每个玩家的连接大概占用80–100kbps。100人同时在线，上行10Mbps是理论底线，实际建议留20%–30%冗余，也就是13–15Mbps。材质包、高频传送、自动备份会额外吃掉一部分。

### 硬盘：NVMe是门槛，不是加分项

玩家跑图时每移动一段就触发大量小文件随机读写，机械盘在这个场景下基本必然掉帧。100人服的系统盘+存档建议80GB起步，长期运营留到240GB以上，并且备份盘要和主盘分开。

| 项目 | 100人（纯净 / Paper） | 100人（模组整合包） |
| --- | --- | --- |
| JVM堆内存 | 10–12GB | 16–32GB |
| 物理内存 | 12–16GB | 24–32GB |
| 上行带宽 | 约10Mbps，建议13–15Mbps | 同左，视距调低可略降 |
| 硬盘 | NVMe，80GB起 | NVMe，200GB+ |

表内是公开行业口径的常见区间，不是精确值——版本、视距、插件数量、玩家的生电规模都会让实际数字上下浮动。

## 二、100人服更适合"群组架构"，而不是单机堆内存

单机32GB跑100人，看起来一步到位，实际问题不少：堆太大GC停顿明显，一台机器挂掉全服掉线，加装插件时也没有缓冲区。

群组架构（Velocity或BungeeCord做前置代理 + 多台子服）是更常见的选择：代理机不加载世界，1–2GB内存就够；每台子服按40–50人的负载配置，比如两台4核8G承接生存和资源世界，再加一台小游戏服。人数继续涨，加子服就行，不用把整服迁移。

对100人这个规模，我倾向的起步组合是：1台2核4G代理 + 2台4核8G子服。按雨云官网公示的档位起始价粗算，125 + 220×2 ≈ 565元/月（实际价格随机型、地区、是否加独立IP浮动，下单页显示为准）。

- 每天开服超过2小时、或要长期挂着当公共服 → 固定计费
- 每天玩一两个小时、碎片化开黑 → 动态计费

## 五、下单前容易漏掉的几个点

**NAT还是独立IP。** 默认是NAT模式（共享公网IP），可开15个端口映射，玩家用IP:端口连接。作为公开服，更稳的做法是加购独立公网IP；部分高防机型独立IP是200元/个，独享该机房的高防能力，而NAT模式下的防御是多用户共享的。

**高防按机型给。** 不同地区机型的防御规格不一样，公开资料里能看到100Gbps、150Gbps、200Gbps几种档位。开了公屏宣传的服，别用普防机器硬扛。

**端口和备案是两件事。** 大陆机房的HTTP业务需要域名备案+过白才能用域名访问，但游戏走IP:端口映射不受这个限制。开服后先确认25565（或你自定义的端口）在控制台和系统防火墙两头都放行了。

**备份。** 面板自带备份和MySQL功能，建议开每日自动备份。存档损坏这件事，一周内你会看到至少三个服主在群里哭。

**服务端和参数。** 插件服选Paper或Purpur，模组服选Forge/NeoForge/Fabric，两者都要的混合端性能和兼容性都打折扣。启动参数用`-Xms`和`-Xmx`同值，加G1GC相关优化；视距设6–8，配合Chunky预生成地图、ClearLag定时清理实体。另外，跑图过程中出现的大量区块加载，用NVMe硬盘的机器会明显轻松。

**基岩版别套用Java版标准。** 基岩版的服务端开销小得多，10人左右一台2核4G就够，不存在"100人乘以Java版系数"这种算法。

## 六、常见问题

**100人一定要16核吗？**
不需要。MC吃单核，一台高主频6核比低频16核更实际。真正要提升的是单核跑分和架构，不是核心数量。

**100人服最低要花多少钱？**
按官方档位起始价粗算，群组方案565元/月起，单机方案要高于超高端档的360元/月。如果只是阶段性冲人数，先用进阶级220元/月 + 动态计费试跑，数据出来再决定，比一次性买高配更省钱。

**用雨云面板还是自己装VPS？**
一键开服的游戏面板适合新手和单端场景，网页操作、支持可视化管理和备份，还能切CPU机型。100人这种规模，建议用游戏云VPS + MCSM面板或群组架构，可控性更高。

**100人服会被攻击吗？**
公屏宣传过的服基本都会。选带高防的机型，配合白名单、连接频率限制和反透视插件，别指望"我们服小没人打"。

**TPS掉到15以下该先改什么？**
先看是主线程卡还是内存问题：用`/spark`或者面板的CPU曲线确认。插件导致的卡顿临时禁用插件就能看出来，内存导致的通常是OOM前的反复波动。两个都不是的话，才考虑升配置。
